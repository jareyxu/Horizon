## [CaLR：因果潜在修正提升扩散模型推理能力](https://arxiv.org/abs/2609.20981) ⭐️ 9.0/10

该论文提出 CaLR（因果潜在修正）框架，通过因果拓扑矩阵与隐式微分将自回归模型和扩散语言模型结合起来，把推理重构为带约束的潜在优化问题。该方法在复杂推理基准上取得了扩散语言模型的最优性能，超越了强自回归基线。 CaLR 同时解决了语言建模中的两个根本性局限：自回归模型在顺序生成时的局部贪婪性，以及扩散语言模型缺乏推理所需的严格因果结构。这一突破有望显著推动基于扩散的推理技术，并惠及整个 AI 生态中的约束求解类任务。 CaLR 采用从专家模型获得的因果拓扑矩阵（CTM）来强制执行逻辑一致性，并通过隐式微分进行梯度引导的"思想修正"，从而在并行生成过程中实现对中间步骤的动态自校正。论文在数独等必须满足严格逻辑约束的任务中展示了优越的鲁棒性。

rss · arXiv cs.AI · 9月22日 04:00

**核验**: 多源印证

**背景**: 自回归（AR）模型逐 token 顺序生成文本，容易陷入"局部贪婪"——即每步选择局部最优的 token，但整体结果未必最优。扩散语言模型（DLM）通过噪声到文本的转化过程而非顺序 token 预测来生成文本，支持并行生成，但往往缺乏推理任务所需的严格因果结构。CaLR 通过借鉴专家模型的因果结构来引导扩散生成过程，从而在并行生成的同时保证逻辑一致性和自我修正能力。

## [爆炸性提示：针对 LLM 代理的新型触发式注入威胁](https://arxiv.org/abs/2609.22510) ⭐️ 9.0/10

该论文提出了一种“爆炸性提示”，这是一种条件性提示注入，在攻击者选择的触发条件满足之前保持休眠状态，从而能够对 LLM 代理实施状态改变攻击。在对九个生产代理的测试中，爆炸性提示的成功率为 43%-83%，而命令式基线的成功率最多仅为 3%。 这种新的攻击向量绕过了传统防御，影响了 OpenAI Codex 和 Claude Code 等广泛使用的开发者工具，构成了重大的安全风险。它凸显了在摄取时检测条件结构以保护实际部署中 AI 代理的必要性。 论文报告称，一个能阻止命令式注入的偏好优化模型仍会执行 11.8%的爆炸性提示，且全部发生在触发轮次。他们提出的检测器 DeFuse 在 5%误报预算下将攻击成功率降至 3.0%，AUC 达到 0.9994，延迟降低 25 倍，但需要长度感知阈值。

rss · arXiv cs.LG · 9月22日 04:00

**核验**: 多源印证

**背景**: 间接提示注入（IPI）是一种攻击，攻击者将对抗性指令嵌入到 LLM 代理检索的内容中，如网页或电子邮件。传统 IPI 在摄取时立即执行，但爆炸性提示在特定触发条件满足前保持休眠，类似于无需训练、推理时后门。这种时间分离使得攻击能够绕过拒绝直接命令的模型，从而对前沿模型和生产代理更有效。

## [无限参数大模型：从实时数据动态生成权重](https://arxiv.org/abs/2609.18842) ⭐️ 9.0/10

该论文提出了无限参数大模型（Infinite-Parameter LLM），一种新颖的架构，利用紧凑的超网络将在线数据转化为共享基础网络的低秩权重调制，从而能够从实时交互中动态学习。与传统静态权重模型不同，该方法在线更新生成器潜在状态的贝叶斯信念，使有效权重在会话过程中不断演化。 这项工作挑战了传统的静态训练范式，使模型无需重新训练即可从实时数据中学习，有望利用用户反馈和纠正来改进已部署的大语言模型。它可能带来更具适应性和个性化的 AI 系统，减少对上下文窗口的依赖，并提升泛化能力。 该模型在保持恒定内存占用的情况下，生成权重的可行空间实际上是无限的。将实时数据表示为权重而非提示词，可以分摊计算成本、释放上下文窗口、跨轮次持久化更新，并且比上下文学习具有更好的泛化能力。评估协议将该方法应用于上下文学习和检索任务。

rss · arXiv cs.LG · 9月22日 04:00

**核验**: 多源印证

**背景**: 缩放定律表明，更大的模型和更多的数据能带来更好的性能，混合专家（MoE）架构通过每个 token 仅激活大型参数库的一小部分来体现这一点。然而，这些模型依赖静态预训练数据，无法整合实时用户交互。超网络是为另一个网络生成权重的神经网络，低秩权重调制是一种高效调整模型的技术。本文结合这些思想，实现了从实时数据动态更新权重。

<p class="archive-item-content">OpenAI 发布 GPT-6 Sol 和 GPT-6 Luna：旗舰级能力下放，API 价格砍半<br>
<br>
OpenAI 推出 GPT-6 家族的两款新模型 Sol 和 Luna，主打“接近旗舰的能力，大幅更低的价格”。API 价格比上一代 GPT-5.6 的促销价再降 50%。<br>
<br>
先理清命名。本月早些时候，OpenAI 发布了 GPT-6 Astra，定位是最强的旗舰模型。这次的 Sol 是中档，Luna 是轻量档，相当于同一代技术的“大、中、小杯”。三款模型用相似的方法训练，所以 Astra 在编程、事实准确性、操作电脑等方面的进步，也带到了更便宜的两款上。<br>
<br>
OpenAI 这次的对比对象主要是 Anthropic 的 Claude。以下数据都来自 OpenAI 自己公布的评测，第三方复现结果还需等待。<br>
<br>
在模拟跨应用处理销售、财务、HR 等业务流程的 AutomationBench 上，Sol 以最高推理强度拿到 33.2%，每个任务成本约 0.27 美元。它超过了最高强度的 Claude Opus 5（26.9%），成本只有后者的 9% 左右，也略高于低强度的 Astra。“推理强度”可以理解为让模型想多久，想得越久，效果越好，但也越贵。<br>
<br>
编程方面，在真实代码库的长任务评测 DeepSWE 上，Sol 得分 68.8%，和 Claude Fable 5 的 69.9% 只差 1.1 个百分点，每任务成本低约 80%。更便宜的 Luna 也有 66.6%，与中等强度的 Opus 5、Fable 5 相当，成本低 93% 到 96%。在让 AI 操作电脑完成任务的 OSWorld 2.0 上，Sol 和 Opus 5 分数几乎打平，成本同样低约 80%。<br>
<br>
对开发者来说，这意味着跑长时间的编程 AI 智能体会便宜很多。OpenAI 透露，内部研究员每天的 token 消耗按 API 价格算，中位数超过 600 美元。模型越能干，这笔账就越重要。<br>
<br>
另一个实用改进是提示缓存。简单说，你反复发送的相同内容，比如系统提示、整个代码库，第二次读取时可以打一折，也就是缓存输入享受 90% 折扣。现在中途调整推理强度或开关工具都不会让缓存失效，开发者还能自己指定缓存的断点。GitHub 表示，这些改进让 Copilot 需要重新处理的 token 减少了一半以上，响应也更快。<br>
<br>
使用体验上，Sol 和 Luna 继承了 Astra 的回答风格：更直接，术语更少，废话更少，回答略短。在事实准确性上，OpenAI 称 Sol 的错误比上一代少了约一半。<br>
<br>
可用情况：即日起，Plus、Pro、Business、Enterprise 和 Edu 用户可以在 ChatGPT Work 和 Codex 中使用这两款模型。免费用户和 Go 用户可以在桌面端用 Luna。普通 Chat 界面暂未上线，ChatGPT 端会在当天分批推送。API 模型名为 gpt-6-sol 和 gpt-6-luna。</p>
