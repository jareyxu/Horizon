## [字节跳动 Seedream 5.5 正式接入豆包，图片设计能力升级](https://news.aibase.cn/news/32217) ⭐️ 7.45/10

<p class="archive-assessment">AI 判断：标题初筛（未依据正文）：仅凭标题只能看出这是一次用 AI 排查生活噪音的记录，具体过程、能否复现及实际效果均未披露，判断依据有限。</p>
<details class="archive-original"><summary>展开原始摘录</summary><p>Our house has a box room, full of boxes that we still haven&#x27;t unpacked from our last move. A couple of weeks ago something in that room started<br>intermittently beeping<br>. The beeps were far enough apart that standing in the room and trying to determine the source of the noise was frustrating, and I really didn&#x27;t want to dig through every one of those boxes. So I had Claude Code build<br>Beep Locator<br>, a software system for triangulating the source of a mysterious beep using multiple devices scattered around the room.<br>Here&#x27;s what Beep Locator looks like after it has been running for a while:<br>You run Python web server to show the primary UI, and then use the QR code or URL to connect as many devices as you can spare to act as listeners - I was using two iPads, a phone, a MacBook Pro and a Surface Ultra.<br>The devices then play noises to each other to help estimate their locations. This didn&#x27;t work particularly well, so I added a &quot;Rough mode&quot; where you can drag their icons around in the space to provide rough locations which are then adjusted based on those sounds.<br>Once that&#x27;s set up, the devices all listen for the beep!<br>I added a clapping mode too so I could test it by clapping my hands in different locations around the room - displayed as diamonds on the map. This helped me gain confidence that it was capable of locating a sound.<br>Beeps show up on the map as an X, plus a line in the &quot;Sounds located&quot; log. You can replay these sounds (from each device in turn) to confirm they are the mysterious beep you are looking for, then click &quot;This is the mystery beep&quot; to mark them as such.<br>Once you&#x27;ve confirmed the mysterious beep frequency the system will listen out for it, measure the interval between beeps, and use the triangulated locations to lock down the most likely location on the map.<br>The system worked as intended. It gave me the position of the beep to within about 40cm, then I dug through that specific pile of boxes and found an ancient carbon monoxide detector that desperately wanted its batteries replaced.<br>How it works<br>When I started working through this problem with Claude it quickly dug up<br>BeepBeep: A High-Accuracy Acoustic-Based System for Ranging and Localization Using COTS Devices<br>, a 2007 paper by Chunyi Peng, Guobin Shen, Yongguang Zhang, Yanlin Li, and Kun Tan. Here&#x27;s that paper&#x27;s abstract:<br>We present the design, implementation, and evaluation of BeepBeep, a high-accuracy acoustic-based ranging system. It operates in a spontaneous, ad-hoc, and device-to-device context without leveraging any pre-planned infrastructure. It is a pure software-based solution and uses only the most basic set of commodity hardware – a speaker, a microphone, and some form of device-to-device communication – so that it is readily applicable to many low-cost sensor platforms and to most commercial-off-the-shelf mobile devices like cell phones and PDAs. It achieves high accuracy through a combination of three techniques: two-way sensing, self-recording, and sample counting.<br>That sounded exactly like what we needed to build!<br>Beep Locator runs a Python web application server that does most of the work. The listening devices then connect to that server via WebSockets and present a UI which requests browser microphone access. The listeners mainly work by recording a 60 second buffer of recent audio. They also run a simple beep detection algorithm (see<br>detector.js<br>), which uses Fast Fourier Transform and a high-pass filter to identify potential beeps. It sends these events to the main server.<br>When a beep is reported, the server has a device play a short chirp (the device with the lowest round-trip time to the server), then asks every listener upload a clip from about 0.6s before the beep to 0.8s after that chirp. This chirp allows the clips to be aligned with each other, a crucial step in locating the beep.<br>How I built it<br>I started this project using Claude Code Cloud via my iPhone, with Opus 5.5 running in Extra thinking effort mode. Here&#x27;s<br>that shared starter session<br>, which began with this prompt against a newly created empty GitHub repository:<br>Write out a problem.md file describing the problem we want to solve<br>There is a device beeping in a room and I cannot find it<br>I want to set up several devices - laptops, phones, iPads - around the room all listening at the same time and have them help triangulate where the beep comes from<br>There needs to be a Python web app which coordinates it all - one device shows a web page for the app, other devices join a URL which turns them into listeners - all via browser WebAudio and WebSockets back to the Python server app<br>Ideally I wouldn&#x27;t need to manually input the relative locations of the devices - it would be amazing if they could play sounds to each other in order to locate each other in 2D space - is that even possible though?<br>That got me<br>this problem.md file<br>. As part of writing that up Claude found and read the BeepBeep paper, which is described in that file.<br>The research looked good, so I told it:<br>Ok try and build it, add a mechanism so you can send new code to the listeners which they will then run automatically - that way I can set everything up in the room and then leave you alone to continue hacking and experiment while I do something else<br>That got me<br>to this point<br>- most of the system was built, but nothing had actually tried running it yet.<br>I cloned the new repository to my laptop and fired up Claude Code... and then<br>Fable 5.2 was released<br>, and this project seemed like an excellent opportunity to put that through its paces.<br>I had Claude Code on my laptop start the server running, then made sure it could both see what was happening<br>and<br>make live changes to the software as it ran.<br>This was already baked into the software: Opus 5.5 had built an<br>installModule()<br>method on the listeners that could be triggered over the WebSocket connection, meaning the admin server could execute arbitrary new code on any of its clients.<br>On some devices, web pages that listen on the microphone request user permission any time the page reloads. The hot-swap module mechanism meant that we could deploy new code without having to manually interact with each of the listening devices in turn.<br>From that point on my involvement was mainly to sit by the laptop chatting with Fable 5.2 about what was going on, and occasionally requesting new features. Here are some of the feature prompts I ran:<br>I think we need to make it so I can drag things around on the map in “rough mode”, where my job is just to put them roughly where they are, then switch out of rough mode and it attempts to get them accurate<br>This gave me the ability to drag listeners around the map.<br>what’s a good way for me to test this I wonder? Can we have it listen for claps, then I could clap and it could identify the location of the clap? [...]<br>Claps should use a different symbol on the map than beeps<br>That added the thing where any time I clapped it would show on the map as a different symbol from the beeps.<br>each symbol on the map should include a HH:MM:SS timestamp<br>That made it easier to spot which symbol likely reflected which real-world sound.<br>The log should show beeps and claps with their timestamps AND have a little play button which, when clicked, replays the recorded noise from each of the listeners in sequence (with clear text on screen showing which listener recorded which snippet) while temporarily turning off microphone recording while that replay plays<br>Now I could replay sounds, making it much easier to identify which recorded clip was the mysterious beep I was looking for.<br>There should be a button next to a recording for “This is the mystery beep” - then I can hit replay to see and then confirm it was the mystery beep if that’s the one I am looking for<br>Then the system can categorize noises in the future to see if they are likely that same mysterious beep and use that information to build a more accurate idea of where it is<br>At this point I was getting close - I had a solid idea of where the beep was coming from, but wouldn&#x27;t it be neat if I could reposition the listeners around that point to get an even finer location?<br>I want a feature for this, I don’t want to have to restart each listening device etc, I want to be able to click a “Reposition the devices” button which lets me switch into repositioning, then I click “Repositioned” and it puts me into Rough mode and asks me to roughly locate them, then I do that and click, then it starts up again. The previous session can be read-only viewed through the app.<br>And since I had one spare device, I then said:<br>add a feature where the map includes a spot that is a suggestion for a location that it would be useful to add a listener at - based on data collected so far<br>Giving Claude Code ears<br>I think the most interesting part of this project is that I demonstrated it&#x27;s possible to<br>give Claude Code ears<br>.<br>Claude doesn&#x27;t have native audio input (yet), but it can run JavaScript and Python code that can analyze audio captured by a microphone.<br>I told it to run a web server with WebSocket connections to multiple listening devices, then had it both run a WebAudio microphone on those devices and hook them up so they could be sent fresh JavaScript code to execute via that WebSocket.<br>Then I could pretty much leave Claude alone, hacking away at the problem, querying the audio logs, and reconfiguring its ears to help it solve the problem.<br>I&#x27;m reminded of a similar hack I heard about at GitHub Universe a few weeks ago, where<br>Martin Woodward<br>told me he had been debugging the<br>GitHub Universe Badge computers<br>by plugging them into a computer via USB-C and then pointing a webcam at their screen, so his coding agent could tell if updates were working correctly or not.<br>Figuring out ways to let coding agents perceive the world around them is a whole lot of fun.<br>Tags:<br>projects<br>,<br>ai<br>,<br>generative-ai<br>,<br>llms<br>,<br>claude<br>,<br>coding-agents<br>,<br>claude-code<br>,<br>claude-mythos-fable</p></details>
